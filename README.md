# MedAudioLab

Настольное приложение для записи, хранения и спектрального анализа звуковых и ультразвуковых сигналов (частоты дискретизации до 768 кГц). Источник сигнала — микрофон или звуковая карта, а также поток данных с микроконтроллера через COM-порт. Построено на PySide6 и pyqtgraph.

## Возможности

### Запись

- Источники: микрофон (через PortAudio / `sounddevice`) и COM-порт (бинарные и текстовые потоки, формат определяется автоматически).
- Частоты дискретизации 44,1 – 768 кГц; поддерживаемые частоты проверяются для выбранного устройства.
- Живой мониторинг: осциллограмма, спектр, индикатор уровня, частота пика.
- Пауза и возобновление записи, защита от потери данных при отключении устройства.
- Сохранение в WAV с выбором разрядности: 16-bit PCM, 24-bit PCM (по умолчанию) или 32-bit float. Если сигнал превышает полную шкалу, файл автоматически сохраняется как 32-bit float, чтобы не было клиппинга.

### Анализ

- Спектр (FFT), спектрограмма (STFT), вейвлет-преобразование Морле (CWT) с ограничением по памяти.
- Цифровые фильтры (ФНЧ, ФВЧ, полосовой) с нулевым фазовым сдвигом.
- Огибающая сигнала, автокорреляция, метрики сигнала (пик, RMS, dBFS, доминирующая частота, спектральный центроид, ширина полосы, THD).
- Детектор импульсов с адаптивным порогом; экспорт найденных импульсов в CSV.
- Гетеродинный сдвиг частоты и растяжение времени для прослушивания ультразвука.
- Открытие WAV, CSV и TXT-таблиц (в том числе с запятой как десятичным разделителем).
- Анализ фрагмента: кнопка «Выделить» в блоке «Фрагмент» выделяет участок на осциллограмме (границы можно тянуть мышью или ввести в секундах); все анализы и метрики считаются только по нему. «Весь сигнал» возвращает полный сигнал, «Сохранить фрагмент» сохраняет фрагмент в WAV. Время на графиках анализа отсчитывается от начала фрагмента.

### База записей

- Записи с названием, пациентом и заметками хранятся в SQLite; поиск по названию, пациенту, дате, заметкам и файлу; открытие на анализ и удаление.

### Экспорт

- Текущий график в PNG, сигнал в WAV или CSV, найденные импульсы в CSV, выделенный фрагмент в WAV (Файл → Экспорт → Выделенный фрагмент как WAV).

## Быстрый старт

Нужен Python 3.11 или новее (на Windows 3.12 проверен).

```bat
git clone https://github.com/diedjest/med-audio-lab.git
cd med-audio-lab
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Запустить можно и как модуль: `python -m app`.

### Где хранятся данные

По умолчанию в `Документы\MedAudioLab`:

| Что | Где |
| --- | --- |
| Записи (WAV) | `Документы\MedAudioLab\records` (папку можно изменить в настройках) |
| База данных и настройки | `Документы\MedAudioLab\med_audio_lab.sqlite3` |

## Настройки

Меню **Правка → Настройки** (`Ctrl+,`):

- папка для сохранения записей;
- разрядность WAV (16 / 24 / 32 float);
- источник сигнала по умолчанию (микрофон или COM-порт);
- частота дискретизации микрофона;
- скорость COM-порта (baud) и частота, с которой анализируются данные из COM-порта.

### Разрядность записи и звуковые интерфейсы Windows

Разрядность WAV-файла — это только формат файла. Реальная точность записи зависит от интерфейса, через который устройство открыто:

- **WASAPI** отдаёт звук в формате, заданном в настройках звука Windows (например, 24 бита). Приложение ставит такие устройства первыми в списке и использует WASAPI-вход по умолчанию.
- **MME** и **DirectSound** отдают только 16 бит, даже если в Windows выбрано 24.

Если на графике при сильном увеличении виден шаг квантования около 3,05·10⁻⁵ (1/32768), значит, выбрано устройство MME / DirectSound. Выберите в списке пункт с пометкой `(Windows WASAPI)`.

## Архитектура

Код разделён на слои. Зависимости направлены только вниз: `ui` → `services` → `core` / `infrastructure`. Слой `core` ничего не знает ни о Qt, ни об оборудовании.

```text
app/
├── constants.py              # Константы и перечисления (частоты, форматы, фильтры)
├── resource_path.py          # Поиск ресурсов в режиме разработки и в собранном .exe
├── core/                     # Слой 1: чистая предметная логика
│   ├── dsp/                  # FFT, STFT, CWT (Морле), фильтры, огибающая, импульсы, метрики
│   ├── models/               # Неизменяемые модели: AudioBuffer, SignalMetrics, CwtResult, ...
│   └── interfaces/           # Абстрактные интерфейсы (аудио, COM-порт, хранилище, экспорт)
├── infrastructure/           # Слой 2: оборудование и хранение
│   ├── audio/                # sounddevice: захват, воспроизведение, кольцевой буфер
│   ├── serial/               # pyserial: чтение бинарных и текстовых потоков (STM32 и др.)
│   └── storage/              # WAV/CSV/TXT, SQLite, экспорт отчётов и графиков
├── services/                 # Слой 3: сценарии работы приложения
│   ├── recording_service.py  # запись, живой мониторинг, сохранение
│   ├── analysis_service.py   # расчёты DSP в фоновых потоках
│   ├── project_manager.py    # записи на диске и в базе данных
│   └── settings_service.py   # настройки
└── ui/                       # Слой 4: интерфейс (PySide6)
    ├── main_window.py        # главное окно и запуск приложения
    ├── viewmodels/           # состояние вкладок (сигналы Qt)
    ├── tabs/                 # «Record», «Analysis», «Library»
    ├── widgets/              # графики, индикатор уровня, выбор устройства
    ├── workers/              # фоновые QThread-задачи
    └── dialogs/              # окно настроек

resources/                    # wavelet_scales.txt, стили (light.qss), иконки
tests/                        # модульные тесты (pytest)
scripts/                      # сборка .exe и вспомогательные скрипты
medaudiolab.spec              # настройки PyInstaller
```

Потоки: аудиоcallback PortAudio только пишет в кольцевой буфер без блокировок; отдельный поток накапливает запись; тяжёлые расчёты (CWT, STFT) выполняются в фоновых `QThread`, интерфейс не блокируется.

## Тесты

```bash
pip install -r requirements.txt   # pytest входит в requirements.txt
pytest
```

Тесты DSP, хранилища и сервисов не требуют оборудования. Для тестов интерфейса без монитора задайте `QT_QPA_PLATFORM=offscreen`.

Дополнительно есть скрипт `scripts/test_record_tones.py`: он проверяет определение тона и гребень CWT на тестовых записях из `tests/data/records`.

## Сборка EXE

Из корня проекта:

```bat
scripts\build_exe.bat
```

Если запускаете PowerShell-скрипт напрямую и политика Windows блокирует `.ps1`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_exe.ps1
```

Скрипт создаёт `.venv`, ставит зависимости из `requirements.txt` и PyInstaller, собирает `dist\MedAudioLab.exe` по файлу `medaudiolab.spec` и проверяет, что результат создан. Параметры:

| Параметр | Назначение |
| --- | --- |
| `-SkipInstall` | не ставить пакеты, использовать готовое окружение |
| `-VenvPath` | другой путь к виртуальному окружению |
| `-DistPath` | куда складывать результат |
| `-WorkPath` | рабочая папка PyInstaller |

Перед пересборкой закройте запущенный `MedAudioLab.exe`, иначе Windows не даст перезаписать файл.

## Зависимости

`PySide6`, `pyqtgraph`, `matplotlib`, `numpy`, `scipy`, `sounddevice`, `soundfile`, `pyserial`, для тестов `pytest` (см. `requirements.txt`). Для сборки exe дополнительно `pyinstaller`.
